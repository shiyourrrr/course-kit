# 教材库：上传电子版、按版本选、按章节喂给生成

> 老师 21:51："书的版本会有不同，所以可以搞一个库，老师可以上传要用到的教材的电子版，还可以选择用哪个版本，用哪个教材来生成 ppt"

## 一句话

教材是**长期复用的资料**（带版本、带章节），和"材料"（课件私有、临时粘贴）分开存放；生成时选「哪本书 · 哪个版本 · 哪些章节」，正文按预算注入提示词。

## 与现有「材料」的区别

| | 材料（已有） | 教材（本设计） |
|---|---|---|
| 归属 | 跟着某一份课件 | 全局库，所有课件共用 |
| 寿命 | 临时，用完可删 | 长期，一次上传反复用 |
| 结构 | 一整块文本 | 书名 / 版本 / 年级 / 章节 |
| 用途 | 补充依据（题库、讲义） | 主依据（这节课讲哪一节） |

两者在生成时都进提示词，**教材优先**、材料补位，共用 20k 字符预算。

## 数据

```
books/<id>/
  meta.json    { id, title, publisher, edition, subject, grade, volume,
                 chapters: [{ no, title, from, to }],   // from/to 是正文里的行号
                 source: "book.docx", chars, uploadedAt }
  text.md      抽取出的纯文本（教材正文）
```

- `books/` 进 `.gitignore` 与 `tools/portable.mjs` 的跳过列表（教材可能受版权约束，绝不进试用包、不进 git）
- 多版本 = 同一 `title` 下的多条记录，列表里显示「书名 · 出版社/版次 · 年级」

## 上传与切章

- 支持 `.docx`（mammoth，已有）、`.md`/`.txt`；PDF 见下一步
- 元数据手填：书名、出版社/版次、年级、册次（必填书名，其余可空）
- **章节自动切分**：按行识别 `第一章` / `第1章` / `1.1` / `第一单元` / `Lesson 3` 等标题行；切不准就让老师手改（章节名 + 起止）
- 上传后显示「识别到 24 章、约 12 万字」，让老师确认

## 生成时怎么用

生成对话框（一句话生成 / 试卷 / 课后作业）加两个控件：

- 教材：下拉（按 书名·版本 列出，默认空 = 不用教材）
- 章节：多选（默认选**当前课件已用过的章节**，没有就空）

注入规则：
1. 选中章节的正文按顺序拼接，作为提示词里"教材依据"块
2. 预算 20k 字符：教材优先，剩余给材料；超了按章节边界截断并明确告知「第 3 章后未纳入，超出预算」
3. 返回 `materialUsage` 里同时列出教材与材料，前端提示"用了教材 X 的第 3-5 章"

## 分三步

1. **教材库基础**：上传 docx/md/txt → 抽文本 → 自动切章 → 列表与元数据编辑；生成时可选「教材 + 章节」，注入提示词
2. **PDF 支持（抽文本，不做"保排版转 Word"）**：引入 `pdfjs-dist` 按页抽文本；**扫描件检测**（抽不到文字就明确报错"这是扫描件，需要 OCR 或原始 Word"）
3. **章节增强**：手改章节边界、按章节预览原文、跨教材对比

## PDF 这件事的实话（老师 21:55 说"PDF 转 Word 不改排版应该有成熟项目"）

查了三个主流开源项目，逐个说清：

| 项目 | 能做什么 | 能不能"不改排版" |
|---|---|---|
| [pdf2docx](https://pypi.org/pypi/pdf2docx/0.5.8/json)（Python, MIT） | 文字型 PDF → docx，重建段落/表格/图片位置 | **近似，不是还原**。字体替换、行距、浮动框都会走样；扫描件完全不支持 |
| [Docling](https://www.infoworld.com/article/3997240)（IBM 开源） | PDF → Markdown/DOCX/JSON，带版面与表格理解 | 结构识别很强，但输出是"重建"的文档，不是原排版；依赖较重（模型） |
| [marker](https://github.com/datalab-to/marker)（PDF→Markdown） | 版面分析 + 表格/公式，效果好 | **GPL 许可**，且要跑模型；输出 Markdown，不是 Word |

结论：
- **"PDF 转 Word 不改排版"是商业软件的护城河**（ABBYY、Adobe），开源只能做到"近似重建"，扫描件一律不行
- **对我们的用途其实不需要**：教材进库是为了让 AI 读正文，**文本就够了，排版无关**
- 所以应用内只做**抽文本**（`pdfjs-dist`，纯 JS、快、无模型）；如果老师确实要一份能改的 Word，用 `pdf2docx` **离线转一次**再把 docx 放进教材库——那是工具，不是应用内功能（老师机器上没有 Python）

## 扫描件怎么办

两条路都不通：抽不出文本、也不该假装能读。界面上直接说清「这是扫描件，读不到文字；请用原始 Word，或用 OCR 转成文本再上传」，不要静默产出一本空白教材。

## 上传方式怎么提示（老师 22:00 提到 "老师应该都有 Adobe"）

有 Acrobat Pro / WPS 会员的老师，**自己导出 Word 再传最省事、排版最完整**；但免费的 Acrobat Reader 不能导出 Word（导出是 Pro/订阅功能），所以应用内的 PDF 抽文本要留着当兜底。

教材库上传区的提示文案（照这个写）：

```
推荐：用 Acrobat / WPS 把 PDF 导出成 Word 再上传，排版最完整
也可以：直接传 PDF（只取文字，排版会丢，不影响生成）
不支持：扫描件（读不到文字），需要先 OCR
```

同时接受：`.docx`（首选）、`.pdf`（抽文本）、`.md` / `.txt`（纯文本）、直接粘贴正文。

## 验收

- 上传一份 docx 教材 → 列表出现「书名·版本」，显示章节数/字数；重启后仍在
- 同书名上传两个版本 → 列表里两条，生成时可分别选
- 生成时选了某章 → `materialUsage` 里出现教材与章节，提示词含该章正文
- 不选教材时行为与现在完全一致
- `books/` 不进 git、不进 dist；导出 HTML 不含教材正文
