## 二、已验证的事实（本机核实）

1. **`@jvmr/pptx-to-html` 1.1.2 完全不实现 autofit**（已核）
   dist 产物里 `normAutofit` / `fontScale` / `lnSpcReduction` / `spAutoFit` 各 **0 命中**；只读了 `bodyPr` 的 `anchor` / `lIns` 等。
   → 文字被裁不是我们写错，是上游丢了 PowerPoint 的"文字自动缩小"语义。
2. **该库把 inset 缺省填 0**（调研）：PowerPoint 缺省 `lIns/rIns=91440 EMU(0.1in)`、`tIns/bIns=45720 EMU(0.05in)`，而它填 0 → 内容整体偏左上，是"掉字"的第一诱因。
3. **KaTeX 字体是内联的**（已核）：`src/assets.mjs` 把 `katex.min.css` 里的 woff2 全转 base64，导出 HTML 里有 20 条 `@font-face`。**公式不会掉字**。
4. **中文正文字体没有内联**（已核）：`font-family: var(--font-sans)` + `"Songti SC", SimSun, "Noto Serif CJK SC", serif` 全靠系统字体栈 → 教室机没装就掉字体、行宽变化。
5. **没有 `sharp`**（已核）：`package.json` 和 `node_modules` 里都没有；导出的图片是原格式 base64 原样内联（`data:image/png`），没有降采样/WebP。
6. **Presenton 的槽位预算是真的**（已核，拉了 `layouts.json` 252 KB）：
   `max_length` ×85、`min_length` ×85、`ellipsis` ×104、`wrap` ×201
   schema：`{layouts:{layouts:[{id,description,components:[{id,position,size,elements:[
   {type,position,size,font:{family,size,color,italic,wrap},name,max_length,min_length,decorative}]}]}]}}`

## 三、autofit 怎么做（方案 1 的技术细节）

**语义**（ECMA-376 / python-pptx）：
- `bodyPr` 三选一：`noAutofit` / `normAutofit` / `spAutoFit`
- `fontScale` 单位是**千分之一百分比**：`62500 → 0.625`，缺省 `100000`
- `lnSpcReduction` 同单位，缺省 0（缩减行距）
- `spAutoFit` = 形状随文长高（top 不动）→ `height:auto` + `min-height` + `overflow:visible`
- `anchor` t/ctr/b → flex `justify-content: flex-start/center/flex-end`
- `wrap="none"` → `white-space:nowrap`

**关键警告**：ECMA-376 **只规定"存下来的结果"，不规定算法**（PowerPoint 算完写进 XML）。
→ 老 PPT 直接读缓存 `fontScale` 就白拿保真；**但 AI 换文案后必须重算**。

**推荐实现（两段，各约 1 人天）**：
1. fork `@jvmr/pptx-to-html`，解析 `bodyPr` 时把 `fontScale` / `lnSpcReduction` / `spAutoFit` 写成 `data-*` 属性，并修正 inset 缺省值（≈1 人天）
2. 渲染后加 fit pass，按框实际尺寸二分字号（≈1 人天）：

```
for each box:  W = cx-lIns-rIns; H = cy-tIns-bIns
  if (spAutoFit) el.style.height = 'auto'
  lo = .3, hi = fontScale ? fontScale/1e5 : 1
  repeat 8:                       # 二分 8 次 ≈0.3% 精度
    mid = (lo+hi)/2; el.style.fontSize = base*mid+'px'
    fits = el.scrollHeight <= H+1 && el.scrollWidth <= W+1
    fits ? (best=mid, lo=mid) : hi=mid
  el.style.fontSize = base*best+'px'
  el.style.lineHeight = 1 - lnSpcReduction/1e5
```

**备选库**：
- `@aiden0z/pptx-renderer`（Apache-2.0，2026-10 新库，`fontScale`+`lnSpcReduction`+`spAutoFit` 都读）—— 生态未验证，当备胎
- `pptxtojson`（MIT，PPTist 的导入层）—— 只解析不渲染，但**按 shape→layout→master 逐级继承**的写法最值得抄
- ❌ `pptx-preview`：npm 标 ISC 但 README 声明源码付费、禁改后发布 → **合规风险，不碰**
- ❌ `PPTX2HTML`：2017 停更
- ❌ **LibreOffice 无头转换不可行**：Impress 没有真 HTML 导出（图片外链、单文件丢图）；`--convert-to pdf` 渲染准但文字进 PDF 不能再填框

## 四、页型槽位预算（方案 2）

把现在计划里的 `limits: {t3: 9}` 升级成区间 + 语义（照抄 Presenton 字段名）：

```json
"slots": {
  "t3": {"max": 9, "min": 2, "decorative": false, "wrap": "word"},
  "t4": {"max": 1, "min": 1, "decorative": true}
}
```

- `decorative: true` 用来排除「01/02/03」这类编号框（实测第 3 页那个 85×106 的「01」框只放得下 1 个字 —— 它压根不是内容槽，不该让 AI 填）
- `min` 用来治「偏空页」（`check.mjs` 现在只会页级报"偏空 ⚠"，没法告诉 AI 该补多少）
- `wrap` 决定估算按行数还是单行

## 五、离线单文件（方案 3、4）

| 项 | 选择 | 说明 |
|---|---|---|
| 中文字体子集 | `subset-font`（BSD-3，harfbuzz wasm） | 按导出 HTML 实际用字动态子集，5–7 MB 全量 → **150~300 KB**；Node API 直接出 woff2 |
| 字体来源 | 思源黑体（OFL-1.1） | 带 RFN 保留字"Source"，子集=修改 → 用自定义 family 名 + 在 HTML 留 OFL 声明 |
| ❌ 字体 | 微软雅黑 / 苹方 | **专有字体，不可内嵌分发** |
| ❌ 工具 | `cn-font-split`（多文件站点懒加载，单文件更肥）、`single-file-cli`（**AGPL-3.0**）、`inliner`（停更）、`vite-plugin-singlefile`（绑 Vite）、`WeasyPrint`（不支持 iframe） | |
| 打印 | **已取消**（用户明确不需要） | 原理记录：`file://` 下 iframe 是 opaque origin，父页读不到 `contentDocument`；`Ctrl+P` 只打当前文档 → 演示块必然印不出来。将来若要打印，只能做"扁平化进主文档 + 每页 A4 容器 + `@page{size:A4}`" |
| 体积顺序 | ①图片降采样+WebP（-50~80%）②相同 base64 去重 ③字体子集 ④逐页样式抽公共表 ⑤删 `mso-*/v:*/o:*`、空 span ⑥svgo ⑦cssnano ⑧html-minifier-terser | 不用 gzip 预压（`file://` 无 Content-Encoding） |
| KaTeX | 已内联（事实更正）；可再按用字子集省 ~150 KB/份 | `output:'mathml'` 是零字体的更轻替代 |

## 六、生成后自检返工（方案 5）

借 PPTAgent（MIT）的闭环思路，但**不上视觉大模型**：
- 导出后在 headless Chromium 里量每页：`scrollHeight>clientHeight`、元素越界、字体回退宽度差
- 把**具体数值**回写 prompt，只重写那一页，限 3 轮，留 diff 日志
- 我们 `tools/check.mjs` 已有量测能力，直接复用
